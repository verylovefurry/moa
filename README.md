# 모아 — Windows 작업 시간과 일정 관리

브라우저를 열지 않는 Windows 데스크톱 앱입니다. 화면은 PySide6의 네이티브 Qt Widgets로 구성하며 WebView·Electron·HTML 렌더링을 사용하지 않습니다.

## 실행

[최신 릴리스](https://github.com/verylovefurry/moa/releases/latest)에서 **Moa.exe**를 내려받아 쓰기 가능한 폴더에 두고 실행합니다. Python과 Qt가 포함되어 있어 별도 설치가 필요 없습니다. 파일 이름은 `Moa.exe`로 유지하세요. 소스 폴더에서는 `시작하기.bat`로도 실행할 수 있습니다.

처음에는 **추적 대상이 비어 있습니다.** 왼쪽 **추적 대상 → 추가**에서 기록할 프로그램이나 URL을 지정하세요. 기본 프로그램과 샘플 작업 시간을 자동으로 등록하지 않습니다.

배포된 실행 파일은 바탕화면 등 원하는 폴더에서 실행해도 Windows 자동 실행을 등록할 수 있습니다. 로그인하면 알림 영역에서 실행되고 등록된 작업의 추적을 시작합니다. 설정에서 변경할 수 있으며 현재 Windows 계정에만 등록하므로 관리자 권한이 필요하지 않습니다.

**소스·테스트 빌드·격리된 데이터 폴더·별도 포트로 실행한 앱은 Windows 자동 실행에 등록하지 않습니다.** 실행 파일의 폴더 위치로 테스트 여부를 판단하지 않습니다. `--stage` 빌드에는 내부 테스트 표시가 포함되어 다른 폴더로 옮겨도 등록되지 않습니다. `--test-mode`, `--no-startup`, `MOA_TEST_MODE=1`로도 등록을 차단할 수 있습니다. 테스트 앱의 설정 변경으로 일반 앱의 자동 실행을 지우지도 않습니다.

테스트 모드는 기본적으로 `test-profile/` 아래 별도 데이터를 사용하고 빈 포트를 자동 선택합니다. 일반 앱의 기록이나 실행 중인 창에 연결하지 않으며, 자동 업데이트로 배포판으로 바뀌지 않습니다.

이미 실행 중이면 기존 창을 앞으로 가져옵니다. 기본적으로 창을 닫아도 알림 영역에서 계속 실행됩니다. 완전히 종료하려면 **파일 → 종료**, **Ctrl+Q** 또는 알림 영역 메뉴의 **종료**를 사용하세요. 닫기 동작은 설정에서 변경할 수 있습니다.

## 화면과 기능

- **작업 달력**: 오늘 강조, 날짜별 누적 시간, 작업별 표시 필터, 월간·목록 보기. **YYYY년 MM월**을 클릭하면 연도와 월을 직접 지정해 이동합니다.
- **날짜별 기록**: 작업·시작/종료·기록 시간, 하루 목표와 자리 비움 제외 시간. 자동 측정한 기록을 조회하는 화면입니다.
- **자동 추적**: 앱 실행과 함께 시작합니다. 등록한 프로그램의 활성 창만 기록하며 여러 프로그램이 열려 있어도 중복 계산하지 않습니다. 필요하면 추적을 일시정지할 수 있습니다.
- **수동 시간 입력 제거**: 수동 기록 추가·삭제와 수동 타이머가 없습니다. 이전 시간 편집 API도 차단합니다. 기존 기록은 보존하며 예전 수동 기록에는 출처를 표시합니다.
- **일정 관리**: 의뢰·할 일의 제목, 의뢰인, 시작일, 선택적인 마감일과 보수, 메모를 등록합니다. 개인 할 일은 의뢰인을 비워둘 수 있습니다.
- **월간 타임라인·목록**: 시작일과 마감일을 기간 막대로 표시합니다. 마감 없는 일정은 점선으로 표시하며 이후 달에도 이어집니다. 상태 필터와 상세 정보, 상태 변경 이력을 제공합니다.
- **일정 진행 상태**: 미착수 → 진행중 → 1차 완료 → 파일 전달 → 보수 수령 → 최종 완료. 각 행의 선택 상자에서 변경하며, 필요하면 이전 상태로 되돌릴 수 있습니다.
- **시간 통계**: 일별 그래프와 작업별 누적·비중 표. 그래프의 날짜를 누르면 달력의 해당 기록으로 이동합니다.
- **추적 대상**: 목록에서 추가·편집·삭제와 사용 여부를 관리합니다. 실행 파일은 찾아보기 또는 실행 중인 프로그램 목록에서 선택할 수 있습니다.
- **CSV 내보내기**: 선택한 달의 기록을 Windows 파일 저장 대화상자로 저장합니다.

## 자동 업데이트

실행 후 약 10초 뒤, 이후 6시간마다 이 공개 저장소의 최신 **정식 릴리스**를 확인합니다. 더 높은 버전의 `Moa.exe`가 있으면 백그라운드에서 내려받고 크기·SHA-256·실행 파일 헤더를 검증합니다. GitHub 로그인이나 개인 토큰이 필요하지 않습니다.

- 준비된 업데이트는 앱을 **완전히 정상 종료할 때** 별도 도구가 설치합니다. 창의 닫기 버튼으로 알림 영역에 숨기는 동작은 종료가 아닙니다.
- **도움말 → 업데이트 확인 → 설치 후 다시 시작**으로 바로 적용할 수도 있습니다.
- Windows 종료 중 설치를 마치지 못한 경우에는 다음 실행 시 준비된 파일을 검증하고 적용합니다.
- 실행 파일만 교체하고 작업 기록·일정·설정·백업은 유지합니다. 이전 실행 파일을 `Moa.previous.exe`로 남기지 않습니다. 검증을 마친 파일을 한 번에 교체하며 다운로드나 교체에 실패하면 기존 버전을 유지합니다.
- **도구 → 설정 → 업데이트**에서 자동 확인·설치를 끌 수 있습니다.

다운로드와 검증 파일은 데이터 폴더의 `updates/`, 마지막 설치 결과는 `updates/last-result.json`에 보관합니다. 소스 실행에서는 자동 설치를 하지 않으며, 실제 업데이트는 배포된 `Moa.exe`에서 동작합니다.

## 자리 비움

기본 기준은 **5분**입니다. 키보드·마우스 입력이 기준 시간 이상 없으면 마지막 입력 시점 이후 임시로 기록된 시간까지 소급해서 제외합니다. 복귀하여 등록한 작업을 활성화하면 새 구간으로 이어 기록합니다. 절전·종료 중의 공백은 합산하지 않으며 자정을 넘긴 시간은 날짜별로 분리합니다.

입력 없이 문서를 읽거나 렌더링을 지켜볼 때는 **도구 → 설정**에서 기준 시간을 늘릴 수 있습니다.

## 웹 URL 자동 감지

앱 자체와 프로그램 추적은 브라우저 없이 실행됩니다. 사용자가 웹에서 하는 작업의 URL을 감지할 때만 기존 Chrome·Edge 확장이 필요합니다.

1. **도구 → 브라우저 확장 연결**에서 연결 코드와 확장 폴더를 확인합니다.
2. Chrome은 `chrome://extensions`, Edge는 `edge://extensions`를 엽니다.
3. 개발자 모드를 켜고 **압축해제된 확장 프로그램을 로드합니다**에서 표시된 폴더를 선택합니다.
4. 확장 아이콘을 눌러 연결 코드를 입력합니다. 모아의 자동 추적이 켜져 있으면 등록된 URL을 감지합니다.

등록한 호스트·경로 및 하위 경로의 활성 탭만 감지합니다. 페이지 내용이나 입력 내용을 읽지 않습니다. 확장 연결용 통신은 `127.0.0.1:3847`에 한정됩니다. 확장 폴더는 앱 임시 압축 해제 위치가 아닌 데이터 폴더 안에 유지됩니다.

## 데이터 보존

- 저장 위치: `%LOCALAPPDATA%\Moa\moa.sqlite3`
- 자동 측정 중 **약 1초마다 SQLite에 저장**합니다. WAL과 FULL 동기화를 사용하며, 정상 종료·Windows 종료 요청 시 기록을 확정합니다. 재실행하면 저장된 기록과 일정을 다시 읽고 자동 추적을 재개합니다.
- 갑작스러운 전원 차단 시에는 마지막 저장까지 복구하며, 저장 직전의 짧은 구간은 남지 않을 수 있습니다. 컴퓨터가 꺼져 있던 시간은 합산하지 않습니다.
- 자동 백업: `%LOCALAPPDATA%\Moa\backups\moa-YYYY-MM-DD.sqlite3`는 하루의 첫 실행/날짜 변경 시 생성합니다. 정상 종료 때에는 `latest.sqlite3`에도 백업합니다. 주 데이터베이스와 백업 모두 자동 기록과 일정을 포함합니다.
- 이전 프로토타입의 `data/moa.sqlite3`는 첫 데스크톱 실행 시 SQLite 백업 방식으로 복사합니다. 원본은 유지하고 이미 있는 데스크톱 데이터는 덮어쓰지 않습니다.
- 새 설치에는 가상 작업 시간을 만들지 않습니다. 이전 버전의 샘플은 **설정 → 샘플 기록 삭제**에서 샘플만 지울 수 있습니다.
- 이전 버전에서 자동 등록했던 기본 추적 대상은 업그레이드 시 한 번 추적 목록에서 제외합니다. 관련 과거 기록과 사용자가 직접 추가하거나 수정한 대상은 보존합니다.
- 기준 시간대는 **Asia/Seoul**입니다.

## 소스 실행·빌드·검증

```powershell
python -m pip install -r requirements-desktop.txt
python desktop.py
python -m unittest discover -s tests -v
```

실행 파일을 다시 만들려면 `python -m pip install -r requirements-build.txt` 후 `python build_desktop.py`를 실행합니다. 결과는 `release/Moa.exe`와 `release/Moa.exe.sha256`입니다. 고정 설치 경로를 사용하려면 앱을 정상 종료한 뒤 `python install_desktop.py --from release/Moa.exe`를 실행합니다. `%LOCALAPPDATA%\Programs\Moa\Moa.exe`를 갱신하고 자동 실행을 등록합니다. `--stage`는 `output/package/`에 테스트 빌드를 생성하며 자동 실행과 정식 설치를 차단합니다.

격리된 개발 실행은 `python desktop.py --data-dir output/qa-data --port 3848 --no-startup --no-update-check`으로 할 수 있습니다. Qt WebEngine은 패키징 대상에서 제외하며 화면은 Qt Widgets만 사용합니다.

## 릴리스 배포

`version.py`의 `APP_VERSION`과 `RELEASE_NOTES.md`를 갱신하고 같은 버전의 태그(예: `v0.4.1`)를 푸시합니다. GitHub Actions가 Windows에서 테스트·빌드한 뒤 실행 파일과 체크섬을 정식 릴리스에 게시합니다. 태그와 앱 버전이 다르면 배포를 중단하며 기존 릴리스 파일을 덮어쓰지 않습니다.

데이터베이스, 로컬 설정·로그, 빌드 출력과 이전 웹 화면은 Git에서 제외합니다. 테스트용 추적 대상은 `tests/fixtures.py`에만 생성되며 배포 실행 파일에 포함되지 않습니다.

기존 추적 규칙과 시간 데이터를 보존하며 일정·상태 이력 테이블을 추가했습니다. `server.py`는 로컬 추적·일정·확장 연결 API를 제공합니다. `/api/timer`, `/api/sessions`, `/api/session-delete`의 수동 시간 변경 요청은 410으로 거절합니다. `dist/`는 이전 웹 프로토타입 소스이며 데스크톱 화면·실행·패키징에 사용하지 않습니다.
